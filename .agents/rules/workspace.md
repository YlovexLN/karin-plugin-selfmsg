# 作用域与清理

适用于本仓库内的一切操作者：AI 助手、维护脚本、以及人工。

## 一、作用域封闭：只动本项目文件夹

**根目录 = 本仓库（`karin-plugin-selfmsg/`）。所有创建、读取、编辑、删除、移动、执行都必须落在它内部。**

禁止：

- 写入仓库外的任何路径——用户目录、桌面、其它项目、盘符根、Karin 安装目录、服务器上的任何路径。
- 删除或移动仓库外的路径，哪怕只是"顺手清理"。
- 改动宿主环境：全局 npm / pnpm 包、其它插件目录、系统配置、环境变量。
- 在运行时引用仓库外的代码或数据：`import` 项目外的文件、添加第三方依赖。

例外只有一处：**系统临时目录**可以用于一次性的验证（解压试跑、生成临时配置），用完立即删除。

判断标准很简单——**一条命令执行完，仓库之外应当没有任何变化。**

部署（把插件放进 Karin 的 `plugins/`、重启服务）属于使用者的动作：
助手不得执行，必须先得到明确同意。

## 二、构建与提交：等指令

以下动作**不得自作主张**，必须等用户明确要求后再执行：

- 构建发布包（`node scripts/pack.mjs`）
- 提交代码：`git init` / `add` / `commit` / `push`、打 tag、发 release
- 修改版本号
- 部署与重启服务

改完代码后只报告"改了什么、验证结果如何"，**是否打包、是否提交由用户决定**。

例外：用户在同一轮对话里明确说了（"打包给我""提交一下"）就直接做，不必二次确认。

## 三、产物清理：一次性即弃，可复用可留

- **一次性产物，用完即删**：临时脚本、临时配置、调试日志、只解压一次就丢的目录。
- **可复用的中间产物，允许保留**：测试生成的 `node_modules/` 桩件、反复用到的解压目录等。
  每次重建既慢又费上下文，留着是合理的——前提是它被 `.gitignore` 覆盖、且不属于项目内容。
- 复用不等于信任：用之前确认它还在、还是对的，变了就重建。
- 清理只针对本次创建的对象，不要顺手删别人的东西。
- 长期保留的只有两类：随包发布的文件，以及 `dist/` 里的发布包（已在 `.gitignore`）。
- 调试脚本若要保留，必须经用户明确同意并放进 `scripts/`，否则一律删除。

自检（应无输出；`node_modules/`、`dist/` 属于允许保留的中间产物，不在此列）：

```bash
find . -maxdepth 2 \( -name '_*' -o -name '*.tmp' -o -name '*.bak' -o -name '*.orig' \) -print
```

## 为什么定这么死

这个插件的全部价值是"运行时接管别人的事件"，它本身没有任何权限边界。
一旦它开始往仓库外写东西，故障就发生在看不见的地方——用户的 `@karinjs/` 被覆盖、
另一个插件的目录被删、宿主机的路径被碰。边界一旦模糊，排查成本远高于收益。

临时文件同理：留下的每一个残留，下次都可能被误认为"项目的一部分"而被提交。
